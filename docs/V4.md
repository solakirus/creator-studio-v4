# Creator Studio v4 — what changed from Creator Studio 3

Built 2026-11-11. Read `CREATOR-STUDIO-3.md` and `HANDOVER.md` first; everything
there still holds. This file covers only the differences.

## Where the code came from

Two copies had split after 2026-10-20:

| copy | had | missing |
|---|---|---|
| laptop (`creator-studio-3` folder, git HEAD e52be43, lots uncommitted) | Library, Templates, notebook pages, task pages, grabber (DB 35) | everything below |
| GitHub `solakirus/creator-studio-3` (Oct 21–29) | phone/Windows self-update (`updater.js`, `electron/main.js` WebUpdate), iPad cover fix (`aspectfix.js`), sync self-heal, Swipe scroll fix | everything above |

were purely additive and both were kept.

## A separate app

Nothing is shared with Creator Studio 3, so both can be installed and the iPad
(where both load from `solakirus.github.io`) can't mix them:

| | CS3 | v4 |
|---|---|---|
| app id (Android + Windows) | com.solakirus.creatorstudio3 | com.solakirus.creatorstudio4 |
| name | Creator Studio 3 | Creator Studio v4 |
| link scheme | cs3:// | cs4:// (widgets, shortcuts, board links, Storyboard back-links) |
| IndexedDB | creator-studio-3 | creator-studio-4 (board.html follows `CS_DB_NAME`) |
| Sync Hub app | creator-studio-3 | creator-studio-4 |
| update site / repo | …/creator-studio-3/ | …/creator-studio-v4/ |
| service-worker cache prefix | cs3- | cs4- (CS3's SW deletes `cs3-*` caches it doesn't own) |
| updater localStorage key | cs3-updater | cs4-updater |

Internal names (`cs3:` IPC channels, `CS3Lib`, `CS3Update`, `cs3lib://`,
`cs3-web` update format) were left alone: they never leave one install.
`app/tests/checks.test.js` fails if any identity line points back at CS3.

## Frames travel with tasks; the Library stays on the laptop

**`app/js/taskframes.js`** (new) and store **`task-frames`** (DB 36, keyPath `uid`).

- `keep()` — on a device with a Library: every Library uid that a *live* task or
  video contains (page spots, extra pages, anything matching `db:li_…` or
  `h:<root>|<path>`) is copied into `task-frames` under that same uid, file
  and (for clips) poster included. Over 30 MB is skipped.
- `MediaLib.load()` puts kept frames into `byUid`/`byPlain` (not into `items`,
  so they never show in the Library's own grids; the Library's copy wins).
  `url`/`posterUrl`/`blobOf` read `src:'tf'` from the store. So `Notebook`,
  task pages and everything else draw them with no other change.
- `sweep()` — on every device: deletes copies nothing live points at.
  Live = task with no day, or task date ≥ today − 21 days; video not
  published, or published < 21 days ago (`Videos.save` stamps `publishedAt`).
  A copy younger than a day is never swept (arrival-order grace).
  Library files are never touched.
- Runs 6 s after start, 4 s after any task/video save, and after a sync that
  brought something in.
- `Notebook.mediaFor` no longer caches "missing", so a frame that arrives later shows.

**Gap 1** — `MediaLib.index()`: a frame copied in by `bringIn` also answers to
its old folder uid (`from`) and path.

**Gap 2** — `ShotTemplates.pageFrom(t)`: a template's shots become a
task-sequence page (≤14 spots, each with the shot's frame and line).
`putOnDay` gives the shoot task that page (shots past 14 stay as plain steps;
the template's notebook pages go on as `morePages`). `newVideo` stores it as
`video.page`; `Videos.schedule` copies it onto the task; the video sheet shows
it as a strip (`TaskFrames.strip`). `QuickAdd.add` accepts `page`, `pageFrom`,
`morePages`.

**Laptop-only** — Content's Library and Templates sections show only when
`window.CS3Lib` exists (Electron). Sync never sends `lib-items`, `lib-blob`,
`lib-poster`, `lib-boards`, `nb-music`, or the `library` setting.
Templates *do* sync (small; the phone's "Change page…" uses them). Sample
templates now have fixed ids and are seeded past sync (`Store.raw`), so a
fresh phone can't push samples over ones edited on the laptop.

## Habits (Year in dots)

Brought over from `creator-studio-3-with-habits.zip` (built on GitHub 2cf6a0f;
see `claude/habits.md` in the Project). Four new files — `js/habits.js`,
`js/screens/habits.js`, `tests/habits.test.js`, `tests/browser/habits.browser.js`
— and the same two insertions: script tags before `views/today.js`, and in
`today.js` the `#habitStrip` div plus `renderList()` → `drawList()` +
`HabitsUI.decorate`. The anchors matched v4's laptop-changed `today.js` exactly.

One v4 change: `TaskPages.attachDefault` skips tasks with `habitId`, so opening
"Drink water" doesn't give it the nine-shot sequence and nine steps. Habits are
settings keys (`habit:<id>`), which sync and back up as before.

## Sync: catching up on new stores

Before: a device on an older build passed over records for stores it didn't
have and moved its cursor past them — after updating it never got them.
Now `sync.js` remembers the stores it has synced (`meta.stores`); when a new
build adds one, the next sync reads the server from 0 once, applying only the
new stores.

## Phone layout fix

Task steps on a task with a shot page: the name input kept its natural width
and pushed the move/remove buttons 40–80 px off a phone screen. The text
column now shrinks, and under 520 px the name wraps under its type tag.

## Logo

`branding/` — three SVG concepts, every icon size for each, and
`logo-options.png`. Clapper Bolt is installed. `node scripts/use-logo.js
<clapbolt|rec4|viewfinder>` copies a set into Android mipmaps + splash,
`build/icon.ico|png`, and `app/icons/`. The Android splash was Capacitor's
white default; it is now #151515 with the logo. Adaptive icon background #151515.
