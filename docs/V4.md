# Creator Studio v4 — what changed from Creator Studio 3

Built 2026-11-11. Read `CREATOR-STUDIO-3.md` and `HANDOVER.md` first; everything
there still holds. This file covers only the differences.

## Where the code came from

Two copies had split after 2026-10-20:

| copy | had | missing |
|---|---|---|
| laptop (`creator-studio-3` folder, git HEAD e52be43, lots uncommitted) | Library, Templates, notebook pages, task pages, grabber (DB 35) | everything below |
| GitHub `solakirus/creator-studio-3` (Oct 21–29) | phone/Windows self-update (`updater.js`, `electron/main.js` WebUpdate), iPad cover fix (`aspectfix.js`), sync self-heal, Swipe scroll fix | everything above |

## A separate app

Nothing is shared with Creator Studio 3, so both can be installed and the iPad
(where both load from `solakirus.github.io`) can't mix them:

| | CS3 | v4 |
|---|---|---|
| app id (Android + Windows) | com.solakirus.creatorstudio3 | com.solakirus.creatorstudio4 |
| name | Creator Studio 3 | Creator Studio v4 |
| link scheme | cs3:// | cs4:// (widgets, shortcuts, board links, Storyboard back-links) |
| IndexedDB | creator-studio-3 | creator-studio-4 (board.html follows `CS_DB_NAME`) |
| Sync Hub app | creator-studio-3 | creator-studio-4 |
| update site / repo | …/creator-studio-3/ | …/creator-studio-v4/ |
| service-worker cache prefix | cs3- | cs4- (CS3's SW deletes `cs3-*` caches it doesn't own) |
| updater localStorage key | cs3-updater | cs4-updater |

Internal names (`cs3:` IPC channels, `CS3Lib`, `CS3Update`, `cs3lib://`,
`cs3-web` update format) were left alone: they never leave one install.
`app/tests/checks.test.js` fails if any identity line points back at CS3.

## Frames travel with tasks; the Library stays on the laptop

**`app/js/taskframes.js`** (new) and store **`task-frames`** (DB 36, keyPath `uid`).

- `keep()` — on a device with a Library: every Library uid that a *live* task or
  video contains (page spots, extra pages, anything matching `db:li_…` or
  `h:<root>|<path>`) is copied into `task-frames` under that same uid, file
  and (for clips) poster included. Over 30 MB is skipped.
- `MediaLib.load()` puts kept frames into `byUid`/`byPlain` (not into `items`,
  so they never show in the Library's own grids; the Library's copy wins).
  `url`/`posterUrl`/`blobOf` read `src:'tf'` from the store. So `Notebook`,
  task pages and everything else draw them with no other change.
- `sweep()` — on every device: deletes copies nothing live points at.
  Live = task with no day, or task date ≥ today − 21 days; video not
  published, or published < 21 days ago (`Videos.save` stamps `publishedAt`).
  A copy younger than a day is never swept (arrival-order grace).
  Library files are never touched.
- Runs 6 s after start, 4 s after any task/video save, and after a sync that
  brought something in.
- `Notebook.mediaFor` no longer caches "missing", so a frame that arrives later shows.

**Gap 1** — `MediaLib.index()`: a frame copied in by `bringIn` also answers to
its old folder uid (`from`) and path.

**Gap 2** — `ShotTemplates.pageFrom(t)`: a template's shots become a
task-sequence page (≤14 spots, each with the shot's frame and line).
`putOnDay` gives the shoot task that page (shots past 14 stay as plain steps;
the template's notebook pages go on as `morePages`). `newVideo` stores it as
`video.page`; `Videos.schedule` copies it onto the task; the video sheet shows
it as a strip (`TaskFrames.strip`). `QuickAdd.add` accepts `page`, `pageFrom`,
`morePages`.

**Laptop-only** — Content's Library and Templates sections show only when
`window.CS3Lib` exists (Electron). Sync never sends `lib-items`, `lib-blob`,
`lib-poster`, `lib-boards`, `nb-music`, or the `library` setting.
Templates *do* sync (small; the phone's "Change page…" uses them). Sample
templates now have fixed ids and are seeded past sync (`Store.raw`), so a
fresh phone can't push samples over ones edited on the laptop.

## Habits (Year in dots)

Brought over from `creator-studio-3-with-habits.zip` (built on GitHub 2cf6a0f;
see `claude/habits.md` in the Project). Four new files — `js/habits.js`,

## Find links on Instagram, TikTok, X profiles

v4 is a new app, so its grab browser (`persist:cs3-grab`, inside v4's own
userData) starts signed out. Instagram then shows a login wall, yt-dlp can't
list a profile, and the old scanner listed the wall's own links (Log In, Sign
Up, followers) as "videos".

- `grab-browser.js`: `open()` spots a sign-in wall on those sites (login
  address, visible password box, or a sign-in dialog) and shows the window so
  the person signs in once; the saved profile keeps it. `postLinks()` scrolls
  a screen at a time and gathers links as it goes, because the grids drop rows.
  `cookieFile()` writes that sign-in as a cookies.txt.
- `grab-builtin.js`: `postLink()` keeps only posts and reels (Instagram
  `/p/ /reel/ /tv/`, TikTok `/video/ /photo/`, X `/status/`, Facebook reels,
  Threads posts), tidied to the post itself; reels are `video`, posts `post`.
  `scan()` sends social profiles straight to the browser (no yt-dlp). Downloads
  of social posts use the app's sign-in via `--cookies` unless a browser is
  picked in settings, and a photo-only post falls back to taking its pictures.
- Test: `app/tests/electron/grab-social.e2e.js` — a mock Instagram (login wall,
  then a grid that keeps only nearby rows) with a stand-in Electron over
  Chromium. 13 checks; the pre-fix code fails 7 of them with the exact links
  from Kris's screenshot.

## Shoot mode

`app/js/screens/shoot-run.js` (new, screen `shoot-run`, `window.ShootRun`):
one shot at a time, full screen — frame (GIF as `<img>`, clip as a muted
looping `<video>`, still), type, line, note, what's next. Got it ticks the shot
exactly as the task screen does (`TaskPages.match`, the page spot and every
step standing for it; all steps → task done) and jumps to the next one not
taken; ‹ › and swipe move without ticking; tapping the picture hides the
chrome; ← → Space/Enter Esc on the laptop. Screen wake lock while open. A task
with no shot page walks its steps instead. Closing calls `params.onChange`.

Ways in: the orange **Shoot mode** button and the **Next up** bar on the shot
page; tapping a picture spot on the shot page (laptop: a *filled* spot — an
empty one still opens the Library picker, and right-click → Pick a shot changes
a frame; phone: any spot); Today's card chip **▶ shoot n/m**, which replaces
the "page n/m" chip that repeated the steps count (the pages stay under the
expanded steps); and the `shoot` shortcut/widget, which falls back to today's
shot-page task when there's no episode day.

The task's shot page canvas now animates (≈12 fps, only while on screen):
`paintPage(ctx, P, t)` passes `t` to `Notebook.draw`, clips are played muted.

Tests: `tests/browser/v4-shoot.browser.js` (25 checks, phone size).
`taskpage.browser.js` now runs as the laptop and checks the new chip.

## Simpler (Nov 11 evening)

- **Shot page only on Shoot tasks** — `TaskPages.attachDefault` needs `kind === 'shoot'`.
  Plain to-dos and habit tasks stay plain; any task can still add a page from
  its Steps ("Add a shot page from Templates…").
- **One add-task form** — Today's + (and a task-library pick) opens
  `TaskForm.open`; Today's own form, `sheetHTML` and `makeSeries` are gone
  (−210 lines). TaskForm gained the workout picker, the library's prefilled
  amount, Today's time options, and copies the page onto repeats.
- **Shots once** — a shot step shows its frame (`.tk-th`, tap → shoot mode on
  it); on a phone (< 900 px) the page drawing starts folded behind "Show the page".
- **One way to shoot** — episode sequences on your tasks get "▶ Shoot it" (vlog-day),
  into `shoot-run`, which shows a step's Reference Library still
  (`t.shots[i].angles[].refIds[0]`) when it has no Library frame.
- **Removed** — `screens/capture.js`, `coverart.js` (verified unreferenced),
  the `planning-quarters`/`notes-list` registrations, all TOOL_ROUTES aliases
  (one key per tile now), the Library's "Phone ⇄ laptop" Library file.
  **Kept**, against the October audit: `stillspicker.js` — the board iframe
  calls `parent.StillsPicker`.
- **Videos screen removed; one-offs are Clips** — `screens/videos.js` is gone
  (Kris: "that's what clips are for"). Templates' "＋ New video from this" is
  now "＋ New clip from this": `ShotTemplates.newClip` saves a Clip in Plan
  with the shot list, hook + notes, and the template's shot page; the clip's
  Shot list shows its frames (`[data-clipframes]`, `TaskFrames.strip`).
  `TaskFrames.wanted()` keeps a clip's page frames until it's posted, then 21
  days; `Data.saveClip` stamps `postedAt` when a clip is saved as published.
  The Videos store and video sheet stay — Series' video ideas use them.
- **Shared helpers** — `U.esc` (escapes & < > " '), `U.midnight`, `U.isoOf`;
  35 local `esc` copies and the identical `midnight`/`isoOf` copies now call
  them. Left alone on purpose: the CSV quoter, `esc2` wrapper and the `t || ''`
  variant (academy, datasets, awards, workout, swiperefs), and every `fmtTime`
  (they print times differently).
- **Without sync** — Settings → *Export for the other device*: every store
  sync carries (all but `Sync.LOCAL_STORES`), task frames copied in first, the
  device's own settings (`backup:`, `sync:`, `library`) left out. The other
  device opens it with *Restore from backup → Add to what's here*. *Export
  everything* is still the full backup, Library included.

Tests: `v4-simpler.browser.js` (16), `v4-devicefile.browser.js` (12).

## Starred groups

The everyday frames, starred on the laptop, kept on every device.
- Store `star-groups` (DB 37, keyPath `id`, **synced**): `{ id, name, items:[uid], created }`.
  `MediaLib.allStars / saveStar / deleteStar / starInto / unstar / starredSet`.
  Deleting a Library frame unstars it everywhere.
- `TaskFrames.wanted()` includes every starred uid, so `keep()` copies them and
  `sweep()` never ages them out; unstarred, they go a day after their copy
  (unless a live task or video still uses them).
- Laptop: Library tab **★ Starred** (counts, MB on the phone, groups with Show
  in Deck / Rename / Delete); Deck Select → **★ Star into…** and, when viewing a
  group (`src = 'star:<id>'`), **Take out of ★ group**; ★ Star in the frame viewer
  (`LibView.starMenu`, laptop only).
- Phone: Content → **Starred** (`screens/starred.js`, `phone:true` in the NAV):
  group pills, grid, full-screen flip. On a shot page step with no frame, a
  dashed **＋** opens `StarPick.open` to give it a starred frame; holding a
  frame changes it.
- Test: `v4-starred.browser.js` (19).

## Templates, hold to swap, a big Deck, the NAS copy (Nov 11 night)

**Templates in Add a task** (`taskform.js`). "Shots from a template" lists the
templates with shots. Picking one names the task (if blank), makes it a Shoot
task, and on save builds `page` with `ShotTemplates.pageFrom(tp)`: the
template's shots and frames, slots undone, extra shots past 14 as steps.
Repeats each get their own deep copy. `TaskFrames.wanted()` now also keeps every
`shot-templates` frame, so a template's frames are on the phone before it is
ever used (a saved template keeps them for good; delete the template and the
21-day rule decides).

**Your own groups.** Starred groups take any name ("Morning coffee", "Morning
wakeup") — ★ Star into… → ＋ Make. A template made of starred frames is the
"same shots every morning" case.

**Hold to swap for today.** `U.onHold(el, fn, ms=600)` (pointer hold, the
following click is swallowed, right-click also works). Shoot mode: hold the
picture → `StarPick` → `ShootRun.setFrame(id, i, uid)`; the first shot shows
"Tap: clean view · Hold: swap the frame". Task page: hold a step's frame
thumbnail → `swapFrame(i)` (laptop: the Library picker; phone: StarPick).
Only the task changes; the toast says the template stays as it is.

**Deck tools for a big library** (`screens/library.js`, `MediaLib.deck`).
Sort (Library order, Newest, Oldest, Name A→Z, Biggest, Kind). Shift-click in
Select mode picks the run between two frames. The grid draws 1,500 at a time
with "Show N more" / "Show all". Source "Unused" = on no board, star group,
task, video or template (uses `TaskFrames.collect`).

**The NAS Shot Library with a copy on this computer.** Any folder in Folders
(the Shot Library, or a NAS folder added with Choose a folder…) can "Keep a
copy…" in another folder. Settings `library.mirrors = { folder: copy }` and
`library.copied` (last run per folder) — local to each computer, never synced.
- `electron/library.js mirrorCopy(from, to)`: copies new and changed files
  (different size, or newer by 2 s+) via `<file>.cs4part` then rename, keeps
  the mtime; skips dot files and top-level `_Deleted`/`_logs`; refuses a copy
  inside the folder or around it. **Never deletes from the copy.** IPC
  `cs3:lib-mirror` (one job at a time, progress `cs3:lib-mirror-step`).
- Runs 20 s after the app starts, 3 s after a grab finishes, and on Copy now.
- `scanAll(list, mirrors)`: when a folder can't be reached and its copy can,
  the copy is read with `scanRoot(copy, folder)` — uids and page ids stay
  `h:<folder>|…`, so tasks, boards, stars and ticked pages keep working; files
  are served from the copy. Library shows a warning on every tab and in
  Folders. When both exist only the folder is read.
- `MediaLib.copyNow / setCopy / copyProblem` (the copy can't be the folder,
  inside or around it, or another Library folder).
- Tests: `app/tests/electron/lib-mirror.test.js` (24, real temp folders, now
  part of `npm test`), `app/tests/browser/v4-tools.browser.js` (42: Deck with
  1,600 frames, Unused, template in the form, Folders copy UI and fallback,
  hold-to-swap in shoot mode and on the task page, synced back).

## The task's Steps + Shot page everywhere (Nov 11, late)

Kris wanted episodes, clips and series videos to plan shots exactly like a task
(Steps with role, frame and NEXT beside the paper Shot page, Next up, ▶ Shoot
mode). Mockups (claude.ai canvas "Creator Studio v4 — shot pages…") were agreed
first: What to film stays plain day rows; a day opens its sequences in place;
the series' parts list stays plain.

How: they **lend the task screen their record** — `app/js/shotlist.js` hosts.
- `ShotList.hostBeat(vlogId, beatId)`, `hostClip(id)`, `hostVideo(id)`:
  `{ kicker, load() → task-shaped { title, page, subs, pageFrom, morePages },
  save(t) }`. The record keeps `page` + `subs` (+ `pageFrom`, `morePages`,
  `hideDone`) and a plain shot list mirrored on every save (`beat.shots` keeping
  ids; `clip/video.shotList` + `.shots` text) for everything that reads shots.
  `shotsSig` notices when that list was changed elsewhere (board, ✦ Suggest
  shots, a tick on the episode's lists): the page is rebuilt from it
  (`ShotList.toTask`), keeping the page's fields. No page and no shots: an
  empty steps page with ＋ Add a shot.
- `screens/task.js` takes `params.host`: load/save go through it, only the
  Steps block renders (`params.embedded`: no title bar, inside another screen,
  `ShotList.embed(container, host, onChange)`); shoot mode
  (`screens/shoot-run.js`, `applyDone/applyFrame`) and the full page editor
  (`task-page`) take the same host.
- **Sequence editor** (`vlog-beat`): Steps first, ✦ Suggest shots under it.
- **Day** (`vlog-day`): the first unfinished sequence opens in place into its
  Steps + Shot page, the rest fold to one line (tap to open), ▶ Shoot it on each
  (its task if it's on your days, else the sequence). The embed is marked
  `data-selectable` so holding a frame doesn't start multi-select.
- **What to film**: plain day rows again (the filmstrip was removed).
- **Clip** Shoot tab: Steps first; "📅 Put the shoot on a day" makes one shoot
  task carrying the clip's page (`ShotList.copyPage`).
- **Series video**: new screen `video-page` — parts down the left (≥900 px,
  plain rows), stage buttons, hook, shoot day (Videos.schedule copies the page),
  Steps. Series cards open it; the video sheet's button opens it too.
- `VlogTasks.write` copies a sequence's page onto its task.
- Removed as redundant: the ShotList list UI (`mount`), the `shots-edit`
  screen, shoot-run's list mode, the shot list template picker.
- Test: `v4-shotlists.browser.js` (36). `suggest` and `v4-frames` follow it.

## Today's steps drop-down (Nov 11, late)

The steps under a task card on Today: the box ticks a step (crossed out; a step
standing for a shot ticks that spot too) and the words are an input — edit and
press Enter or leave it. Tapping the words no longer ticks. Renaming a step that
stands for a shot renames the shot on the page (steps are named after their
shots, taskpages.js). Test: `v4-substeps.browser.js` (11, phone + laptop).

## Sync: catching up on new stores

Before: a device on an older build passed over records for stores it didn't
have and moved its cursor past them — after updating it never got them.
Now `sync.js` remembers the stores it has synced (`meta.stores`); when a new
build adds one, the next sync reads the server from 0 once, applying only the
new stores.

## Phone layout fix

Task steps on a task with a shot page: the name input kept its natural width
and pushed the move/remove buttons 40–80 px off a phone screen. The text
column now shrinks, and under 520 px the name wraps under its type tag.
